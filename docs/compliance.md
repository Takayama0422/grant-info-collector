## 1. 題材（データセット）の選定

### 1-1. 選んだもの

**e-Govデータポータルに登録された「補助金」「助成金」「公募」に関するデータセットの、府省をまたいだ一覧。**

### 1-2. 選定理由

補助金・入札・公募の公開情報は**府省ごとにばらばらの場所に置かれており**、
中小企業・個人事業主が「自社が使える制度はどこに出ているか」を調べるには、
省庁のサイトを1つずつ開いて回るしかない。この探し回る作業そのものを1枚の表に置き換えられるため、
**発注者が自分の業務に重ねて想像しやすい**題材だと判断した。

### 1-3. 個人情報を含まないことの確認

収集する項目は、データセット名・公表組織名（府省名）・概要・データ形式・更新日・詳細ページURLのみである。
**氏名・住所・連絡先などの個人に関する情報は取得しない。**
交付先の一覧（個人事業主の氏名を含む可能性がある）は**収集対象から外している。**

### 1-4. 補助金の「公募情報」そのものを扱えなかった理由（正直に記録する）

当初は「募集中の補助金の公募情報（金額・受付期間つき）」を集めることを狙った。
しかしカタログを実際に検索した結果、**機械で読める形の公募情報は存在しなかった。**

| 検索した条件 | 該当件数 |
|---|---|
| `補助金` | 202 件 |
| `補助金` かつ CSV 形式のデータあり | **0 件** |
| `入札` かつ CSV 形式のデータあり | **0 件** |
| `公募` | 65 件（大半は府省サイトのページへのリンク） |

このため、**金額・受付開始日・受付締切日の3列は空欄のまま出力する。**
それらしい値を推定して埋めることはしない（`docs/measurement.md` および出力ファイル内の注記にも明記）。

> 出典：e-Govポータル　（https://www.e-gov.go.jp）

> （本コンテンツを編集・加工等して利用する場合の記載例）
> 「○○動向調査」（デジタル庁）（当該ページのURL）をもとに○○株式会社作成など

### 2-2. 規約本文 — 公共データ利用規約（第1.0版）PDL1.0（2026-08-25 取得、HTTP 200）

- URL：https://www.digital.go.jp/resources/open_data/public_data_license_v1.0

原文引用：

> 当ウェブサイトで公開している情報（以下「コンテンツ」といいます。）は、別の利用ルールが適用されるコンテンツを除き、どなたでも以下の1.1.から1.7.に定める利用ルール（…）に従って、**複製、公衆送信、翻訳・変形等の翻案等、自由に利用できます**（…）。**商用利用も可能です。**

> なお、数値データ、簡単な表・グラフ等は著作権による保護の対象ではありませんので、これらについては本利用ルールの適用はなく、自由に利用できます。

> 1.1. 出典の記載について
> 本コンテンツを利用する際は出典を記載してください。
> （出典記載例）出典：D庁ウェブサイト（当該ページのURL）、PDL1.0（規約原文ページのURL）
> 本コンテンツを編集・加工等して利用する場合は、上記出典とは別に、編集・加工等を行ったこと及びその主体を記載してください。

> 1.2. …外部データベース等とのAPI（Application Programming Interface）連携等により取得しているコンテンツについては、その提供元の利用条件に従ってください。

> 1.7. …本利用ルールは、令和6年7月5日に定めたものです。

### 2-3. 判定

**利用可。** 複製・翻案・再配布・商用利用が明示的に許諾されている。

**守る義務は次の2点だけである。**

1. **出典を記載する**
2. **編集・加工を行ったことと、その主体を記載する**

**本ツールが実際に出力するのは次の文言である**（`src/notice.js`。CSVの末尾行とXLSXの「出典・利用条件」シートに埋め込む）。

```
出典：e-Govデータポータル（デジタル庁）（https://data.e-gov.go.jp/data/dataset）
利用条件：公共データ利用規約（第1.0版）PDL1.0（https://www.digital.go.jp/resources/open_data/public_data_license_v1.0）
加工の有無：あり。「データセット検索結果」（デジタル庁 e-Govデータポータル）（https://data.e-gov.go.jp/data/dataset）をもとに grant-info-collector が作成。
加工主体：grant-info-collector（本ツールの実行者）。デジタル庁が作成した未加工の情報ではない。
未取得の列：金額・受付開始日・受付締切日は、出典側のカタログに項目が無いため空欄とする（推定値は入れない）。
```

### 2-4. PDL1.0 の 1.2. への対応

規約 1.2. には「API連携で取得しているコンテンツは提供元の条件に従うこと」とある。
本ツールが取り出すのは**カタログ自身のメタ情報（データセット名・公表組織名・概要・形式・更新日）だけ**であり、
各府省のサイトにある実データファイルは**一切ダウンロードしない。**
出力する `url` 列は、e-Govデータポータル内の詳細ページへのリンクである。

## 3. robots.txt の確認 — ここが判断の分かれ目だった

### 3-1. 確認した内容（2026-08-25）

| URL | 結果 |
|---|---|
| `https://data.e-gov.go.jp/robots.txt` | **HTTP 404**（ホスト直下には robots.txt が無い） |
| `https://data.e-gov.go.jp/data/robots.txt` | **HTTP 200** |

`https://data.e-gov.go.jp/data/robots.txt` の原文（全文）：

```
User-agent: *
Disallow: /dataset/rate/
Disallow: /revision/
Disallow: /dataset/*/history
Disallow: /api/
Crawl-Delay: 10
```

### 3-2. どちらを正とするかが、仕様上あいまいだった

robots.txt の決まり（RFC 9309）では、**ホスト直下の `/robots.txt` だけが正式な指定**である。
その意味では、ホスト直下が404の本サイトには**拒否指定が存在しない**ことになる。

一方、このサイトはカタログ機能を `/data/` の下に載せており、
そのカタログが自前の robots.txt を `/data/robots.txt` に置いている。
このファイルに書かれた `Disallow: /api/` は、
カタログの位置を基準に読めば `/data/api/` を指していると解釈できる。

### 3-3. 厳しい側を選んだ

**本ツールは、拒否指定が存在するものとして扱う。**

- `/data/api/` 配下（CKAN の公開API）へは**接続しない**
- `Crawl-Delay: 10` に従い、**1リクエストごとに10秒以上空ける**
- 使うのは `/data/dataset`（通常のHTML検索ページ）のみ。ここは拒否対象ではない

APIを使えば数秒で終わる処理を、あえて2分以上かけて行っている。
**速さより、相手の意思表示に従うことを優先した結果である。**

この判断は `src/robots.js` に実装し、`tests/robots.test.js` で
「`/data/api/…` は拒否、`/data/dataset` は許可」と判定できることを検証している。

## 4. 見送った候補 — jGrants（Jグランツ）

元の題材（補助金の公募情報）に最も近いのは、デジタル庁が提供する jGrants の補助金情報取得APIだった。
**検討したが、不採用とした。**

### 4-1. APIは実在した

- APIドキュメント：https://developers.digital.go.jp/documents/jgrants/api/
- OpenAPI仕様書（2026-08-25 取得、約39KB）：
  https://files.microcms-assets.io/assets/7c793323a46a46b7bb9a2ac7d0023301/2bad5ef79255448f8381d9cf2a14dbfc/jgrants-api.yaml

仕様書冒頭の原文引用：

```yaml
openapi: 3.1.0
info:
  title: 補助金情報取得API
  version: "1.0"
servers:
- url: https://api.jgrants-portal.go.jp/exp
```

### 4-2. 不採用の理由：**利用規約の本文を確認できなかった**

`https://www.jgrants-portal.go.jp/robots.txt`（2026-08-25 取得、HTTP 200）の原文（全文）：

```
User-agent: *
Disallow: /
Allow: /index.html
```

**サイト全体への自動アクセスを拒否している。**
API利用規約は `https://www.jgrants-portal.go.jp/open-api` に掲載されていると判断できたが、
このパスは上記の `Disallow: /` に含まれる。
**拒否されている経路へは取りに行かない**という方針に従い、規約本文を取得していない。

代替経路も確認したが、規約本文は見つからなかった。

- デジタル庁 開発者サイトの jGrants ドキュメント：API仕様のみ。利用規約へのリンクなし
- OpenAPI仕様書本文：`securitySchemes` の定義なし、レート制限の記載なし、規約への言及なし

その結果、次の4点が**不明のまま**となった。

| 確認項目 | 状態 |
|---|---|
| 取得データの再配布・再掲載の可否 | 不明 |
| 商用利用・ポートフォリオでの利用の可否 | 不明 |
| レート制限の指定 | 不明 |
| APIキー・利用申請の要否 | 不明 |

### 4-3. 判断

**「たぶん大丈夫」で進めない。** 再配布の可否が確認できない相手のデータを、
公開リポジトリへコミットする成果物の材料には使えない。
規約が明示されている e-Govデータポータルへ切り替えた。

### 4-4. 意図的に行っていないこと

- **jGrants API へのリクエストを1回も送っていない。** 規約が未確認の段階では送らないと判断した
- `robots.txt` の回避、User-Agent の偽装、アーカイブ経由での規約取得のいずれも行っていない

## 6. 実際に守っている運用

**アクセス頻度**

- 1リクエストごとに **10秒以上**の間隔を空ける（`robots.txt` の `Crawl-Delay: 10` に従う）
- **並列リクエストを行わない。** 必ず1本ずつ順番に取得する（`src/http.js`）
- 1回の実行で辿る組織数とページ数に上限を設ける（`config/sources.json` の `maxOrganizations` / `maxPages`）。
  既定では **1回の実行あたり14リクエスト**で終わる
- 失敗しても即時に繰り返さず、間隔を2秒→4秒と延ばす。**3回失敗したら止める**
- **`429` / `503` を受けたら再試行せずその場で中止する**（`src/http.js` の `StopRequested`）

**送信元の明示**

- User-Agent：`grant-info-collector/1.0 (+https://github.com/Takayama0422/grant-info-collector)`
- **正体を隠さない。** User-Agent の偽装、robots.txt の回避、その他の検知回避は行わない

**robots.txt**

- 実行のたびに、ホスト直下とカタログ直下の robots.txt を**両方**取得して判定する
- 拒否されている経路には接続しない（接続しようとすると実行を止める）

**キーの扱い**

- 本ツールは認証情報を使わない。`config/sources.json` に鍵を書く箇所は無い
- 万一エラーメッセージに認証情報らしき文字列が混ざった場合に備え、出力時にマスクする（`src/redaction.js`）

**再配布**

- 取得結果（`reports/example-run/`）と、取得した応答の写し（`fixtures/`）をリポジトリに含めている
- これは PDL1.0 が複製・再配布を明示的に許諾しているために可能な扱いである
- 両方に出典・加工主体の記載を含めている
