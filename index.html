業務自動化ツール

補助金・助成金の公募情報を、
自動で収集して表にする。

e-Govデータポータル（デジタル庁）の公開データから、補助金・助成金・入札公募に関する情報を集め、 CSVとXLSXの表に整形して出力します。府省ごとにばらばらのページを1件ずつ開いて Excel へ書き写していた調べ物が、コマンド1つに置き換わります。 107件の収集を 132.6 秒（実測）で完了します。

出力CSVを見る（107件・実物） README を読む 計測の生記録を見る 規約確認の記録を見る

このツールが何をするか

設定ファイルに登録したキーワードで公開カタログを順番に検索し、 公募名・実施主体・分類・対象地域・概要・データ形式・更新日・詳細URLを1件ずつ抜き出して、 1枚の表（CSV / XLSX）にまとめて出力します。ネットワークに接続できない環境でも、 同梱した応答の写しからまったく同じ107件を再生成できます（実測 0.1 秒）。

  • 情報源ごとの巡回間隔・タイムアウトなどは設定ファイル（config/sources.json）で調整できます。
  • 認証が必要な情報源は既定で拒否します（明示的に許可した場合のみ対象にできます）。
  • 取得元の利用規約・robots.txt を事前確認できなかった情報源は対象にしません。
  • 金額・受付開始日・受付締切日は空欄になります。出典側のカタログにその項目が無いためで、推定値は入れていません。

処理の流れ

取得 → 整形 → 出力の3段階。詳しい設計は docs/design.md を参照してください。

  • 1

    取得

    設定ファイルの情報源を順に読み、公募情報を1件ずつ収集します。ネットワークなしのモック経路もあります。

  • →
  • 2

    整形

    収集結果を共通の形（GrantRecord）に揃え、列の順序・表記をそろえます。

  • →
  • 3

    出力

    CSVとXLSXの2形式で書き出します。文字化け・数式インジェクション対策済みです。

手作業と比べると

「手作業」の側は外挿（推計）です。実測ではありません。 無作為に選んだ10件を実際に手作業して1件あたりの時間を測り、107件ぶんに掛けた値です。 1件ごとの秒数・選び方・計算式は docs/measurement.md にそのまま残しています。

107件を集めて表にするまで
項目 手作業 本ツール
1件あたり 17.7 秒（10件の実測の中央値） 1.24 秒（実測 132.6秒 ÷ 107件）
107件ぶん 約 31.6 分（外挿：17.7秒 × 107件） 132.6 秒＝約 2.2 分（実測）
表への整形（CSV / XLSX） 上記の手作業に含む 同じ実行の中で自動生成（別作業なし）

この差は「外挿 − 実測」であり、両方を実測して比べたものではありません。 手作業の17.7秒はページ構造を知っている開発者本人が測った値で、実務にかかる時間の下限に近い値です。 本ツールの132.6秒は、その大半が待ち時間です（robots.txt の Crawl-delay: 10 に従い、 1リクエストごとに10秒空けています）。速くすることもできますが、そうしていません。

確認・再現の手順

発注判断のために、以下から実際の状態を確認できます。

  • 利用規約・robots.txt の事前確認記録
    docs/compliance.md — 対象データ源ごとに、判定（利用可・条件付き可・不可）の根拠を記録しています。
  • Dockerでの再現手順
    README「⑥ Dockerでの再現手順」 — ローカルに Node.js を入れずに、Docker のみで同じ結果を再現できます。
  • 仕組み図
    docs/design.md — 取得・整形・出力の各段階を図で確認できます。
  • 計測の生記録
    docs/measurement.md — 手作業10件の1件ごとの秒数、対象の選び方、中央値、外挿の計算式をそのまま残しています。 実測と外挿を区別して記載しています。
  • 実行して出てきたファイルそのもの
    reports/example-run/ — CSV（107件）とXLSX。出典・加工主体の記載も含まれています。
  • できないこと・制約
    README「⑧ できないこと・制約」 — 対象範囲や既知の限界を正直に記載しています。
