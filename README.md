# Grant Info Collector

補助金・助成金・入札公募に関する公開情報を自動で収集し、表（CSV / XLSX）に整形して出力するツール。

**状態：完成。実データの収集まで動作します。**
本ページに載せている数値は、すべて実際に測った値か、実測から計算した推計です。
どちらであるかを項目ごとに明記しています。**推測で書いた数値はありません。**

- デモページ（GitHub Pages）: https://takayama0422.github.io/grant-info-collector/
- 出力の実物: [`reports/example-run/`](reports/example-run/)（実行して出てきたファイルそのもの）
- 出典: **e-Govデータポータル（デジタル庁）** https://data.e-gov.go.jp/data/dataset
- 利用条件: **公共データ利用規約（第1.0版）PDL1.0**
- 加工主体: **grant-info-collector**（本ツールの実行者）。デジタル庁が作成した未加工の情報ではありません

## ① 出力の実物

実行して出てきたファイルをそのまま置いています。手で書いたサンプルではありません。

| ファイル | 中身 |
|---|---|
| [`reports/example-run/grants.csv`](reports/example-run/grants.csv) | 107件の一覧。Excel でそのまま開けます（BOM付きUTF-8）。末尾の `#` 行が出典・加工主体の記載 |
| [`reports/example-run/grants.xlsx`](reports/example-run/grants.xlsx) | 1枚目が一覧（107行）、2枚目「出典・利用条件」が出典・加工主体の記載 |

出てくる表は次の形です（実データから抜粋）。

| 公募名 | 実施主体 | 分類 | データ形式 | 更新日 |
|---|---|---|---|---|
| 補助金等の手続の簡素化 | 農林水産省 | 補助金 | — | 2025-04-11 |
| 令和３年度_人事院調達情報 | 人事院 | 公募・入札公告 | HTML / PDF | 2025-06-27 |

それらしい値を推定して埋めることはしていません（[`docs/compliance.md`](docs/compliance.md) 1-4）。

## ② 1行で「何の手作業がなくなるか」

府省ごとにばらばらに置かれた補助金・助成金・入札公募のページを1件ずつ開いて内容を読み取り、
Excel へ書き写す作業が、コマンド1つに置き換わります。

## ③ before / after

**「before」は外挿（推計）です。実測ではありません。**
無作為に選んだ10件を実際に手作業して1件あたりの時間を測り、それを107件ぶんに掛けた値です。
計測の生記録は [`docs/measurement.md`](docs/measurement.md) にあります。

| 項目 | before（手作業） | after（本ツール） |
|---|---|---|
| 1件あたりの所要時間 | **17.7 秒**（10件の**実測**の中央値） | **1.24 秒**（132.6秒 ÷ 107件・**実測**からの割り算） |
| 107件ぶんの調査 | **約 31.6 分**（**外挿**。17.7秒 × 107件） | **132.6 秒＝約 2.2 分**（**実測**） |
| 通信せず同じ107件を作り直す | 該当なし | **0.1 秒**（**実測**。同梱の固定データを使用） |
| 表への整形（CSV / XLSX 作成） | 上記の手作業に含む | 収集と同じ実行の中で自動生成（別作業なし） |

**この差は「外挿 − 実測」であり、両方を実測して比べたものではありません。**

手作業の17.7秒は**本ツールの開発者本人**が、ページ構造を知っている状態で測った値です。
そのため**実務にかかる時間の下限に近い値**であり、初めてこのサイトを見る人はより時間がかかります。
短く見せるために都合のよい値を選んではいません。

本ツールの132.6秒は、**その大半が待ち時間**です。
相手のサーバへ1リクエストごとに10秒の間隔を空けているため（`robots.txt` の `Crawl-delay: 10` に従う）、
14回の取得で約130秒が待ちに充てられます。速く取りに行くこともできますが、**そうしていません。**

## ⑤ 利用規約・robots.txt の確認記録

外部へアクセスする前に、対象サービスの利用規約と `robots.txt` を確認し、
判定とその根拠を [`docs/compliance.md`](docs/compliance.md) に記録しています。**確認プロセスも成果物です。**

- **採用：e-Govデータポータル（デジタル庁）** — PDL1.0 で複製・翻案・再配布・商用利用が明示許諾。認証不要
- **不採用：jGrants** — `robots.txt` が全経路を拒否しており、**利用規約の本文を確認できなかった**ため見送り。
  APIへのリクエストは1回も送っていません
- **不採用：e-Stat API** — 規約は明示されているが**利用登録が必須**で、「第三者がそのまま動かせる」条件に合わない
- `robots.txt` の解釈が仕様上あいまいな箇所（ホスト直下が404、カタログ直下に存在）では、
  **厳しい側に従って** `/data/api/` へは接続していません
- User-Agent で正体を明示しています。**偽装・回避の細工は一切していません**

## ⑥ Docker での再現手順

ローカルに Node.js は不要です。

```bash
# 依存を入れて検証（構文チェック＋テスト47件）
docker run --rm -v "$PWD":/app -w /app node:22-bookworm-slim \
  sh -c "npm ci && npm run validate && npm test"

# 通信せずに実行（同梱の固定データから107件を再生成・約0.1秒）
docker run --rm --network none -v "$PWD":/app -w /app node:22-bookworm-slim \
  node src/cli.js --config config/sources.json --output reports/latest --offline

# 実際にネットワークから収集（約2分。相手に10秒間隔を空けるため）
docker run --rm -v "$PWD":/app -w /app node:22-bookworm-slim \
  sh -c "npm ci && node src/cli.js --config config/sources.json --output reports/latest"
```

`docker compose build` / `docker compose run --rm collector` でも同じことができます。

**何をもって「動作確認できた」とするか（この基準で確認済み）**

1. `npm ci` が新規に成功する
2. `npm run validate`（構文チェック）が成功する
3. `npm test` が **47件すべて通過**する
4. 通信ありの実行で `grants.csv` / `grants.xlsx` が生成され、**107件**入っている
5. **通信を遮断した状態**（`--network none`）でも同じ107件が生成される
6. 出力ファイルの中に**出典と加工主体の記載**が入っている

## ⑧ できないこと・制約

- **金額・受付開始日・受付締切日は取れません。** 出典側のカタログにその項目が無いためで、空欄のまま出力します
- 集めているのは**カタログのメタ情報**（データセット名・公表組織・概要・形式・更新日・詳細URL）です。
  各府省サイトの実データファイルはダウンロードしません
- 認証情報が必要な情報源は既定で拒否します（設定で明示的に許可しない限り使えません）
- 定期実行（スケジューラ）の仕組みは含みません
- 利用規約・`robots.txt` を確認できない、または自動アクセスを拒否している情報源は対象にしません
- 取得元がページ構造を変えた場合、追随するまで収集が止まる可能性があります。
  そのときも同梱の固定データで動作は再現できます
- 個人に関する情報（氏名・住所・連絡先）は取得しません。交付先一覧は対象外にしています
- 金額・期日はテキストのまま保持する方針のため、表記ゆれの統一は行いません

## ⑨ セキュリティ上の判断（依存パッケージの指摘について）

**確認日：2026-08-25。** Docker上（`node:22-bookworm-slim`、`npm ci`後）で `npm audit` を実行し、
実際の指摘内容を確認したうえでの判断です。数値はすべてこのとき実際に確認したものです。

**指摘の内容**

- 件数・深刻度：**中程度（moderate）2件**。高（high）・重大（critical）は0件
- 対象：本ツールがExcel出力に使っている部品 **`exceljs`** が内部で使っている、
  ID（重複しない識別子）を作るための部品 **`uuid`** に対する指摘です。`exceljs` 自体の不具合ではありません
- 指摘の中身：`uuid` が持ついくつかの作り方（`v3`・`v5`・`v6`）のうち、
  呼び出し側が「書き込み先のメモリ領域」を自分で指定して呼んだ場合に、範囲チェックが足りない
  というものです（CVSS 7.5、[GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq)）

**このツールでは実害が生じにくい理由**

- `exceljs` が `uuid` を呼んでいる箇所はコード上1か所だけで、しかも使っているのは
  指摘対象外の作り方（`v4`。乱数で作る版で、書き込み先メモリを自分で指定しない）です。
  指摘されている `v3`／`v5`／`v6` の経路そのものを通っていません
- その1か所は、Excelの「条件付き書式の拡張ルール」にIDを振る処理です。
  本ツールの出力コード（`src/xlsx.js`）はこの機能を使っていないため、実行時にこの処理自体が呼ばれません
- 本ツールは、収集済みの公開データを決まった列へ流し込んでExcelファイルを**書き出すだけ**の構成です。
  外部から受け取ったファイルを読み込む・アップロードを受け付ける、といった**外部入力を扱う経路がありません**。
  そのため、悪意あるデータがこの部品に渡る道筋自体が存在しません

以上により、**実害は「起きない」ではなく「起きる経路が見当たらない」という意味で低い**と判断しています。

**自動修正を採用しなかった理由**

`npm audit fix --force` を使い捨ての複製（本体とは別のコピー）で実際に試し、結果を確認しました。

- `exceljs` が **4.4.0（2023年10月公開・現行の最新安定版）から 3.4.0（2019年11月公開・約6年前）へ引き下げられました**
- しかも指摘がゼロにはなりません。3.4.0が依存する別の部品（`fast-csv`・`tmp`）に**新たに3件**の指摘が出ました。
  うち1件は**高（high）**で、シンボリックリンクを使った意図しないファイル書き込み（パストラバーサル）の指摘です
- つまり自動修正は、中程度2件を、高1件を含む3件に**悪化させたうえで**、6年前の作りへ戻す結果になります。
  採用していません

現在使っている `exceljs@4.4.0` は、この確認時点での最新安定版です
（次のバージョンはプレリリース版のみで、正式版はまだ出ていません）。上流側の対応待ちの状態です。

**今後どうなったら対応するか**

- `exceljs` が `uuid` の修正版（11.1.1以降）を取り込んだ**安定版**を公開したら、それに追随して更新します
- それまでの代替手段として、`package.json` の `overrides` 機能で `uuid` だけを11.1.1系へ固定する方法を
  使い捨ての複製で検証済みです。この方法なら `exceljs` を4.4.0のまま保ったまま
  **指摘0件**にでき、既存のテスト47件もすべて通過することを確認しています。
  今回は反映を見送りましたが（実害が生じにくいと判断しているため急いでいません）、
  対応する場合はこの方法をまず使います
